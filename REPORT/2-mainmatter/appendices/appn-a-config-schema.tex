\chapter{Configuration Schema Reference}
\label{appn:config}

This appendix documents the full JSON configuration schema accepted by
the simulator, validated by \texttt{engine/config\_validator.py}.

%% -----------------------------------------------------------------------
\section*{Top-Level Keys}

\begin{description}
  \item[seed] (integer) Random seed for reproducibility.
  \item[time\_horizon] (integer) Number of simulation days.
  \item[skus] (list of strings) SKU identifiers, e.g.\
        \texttt{["SKU\_A", ..., "SKU\_E"]}.
  \item[sku\_properties] (object keyed by SKU) Per-SKU physical properties.
  \item[nodes] (list of node objects) One entry per stocking location.
  \item[edges] (list of edge objects) One entry per transport lane.
  \item[disruptions] (list, optional) Supply disruption events.
\end{description}

%% -----------------------------------------------------------------------
\section*{SKU Properties Object}

\begin{verbatim}
"sku_properties": {
  "SKU_A": {
    "item_id": "SKU_A",
    "volume_per_unit": 0.004,
    "weight_per_unit": 0.8
  },
  ...
}
\end{verbatim}

%% -----------------------------------------------------------------------
\section*{Node Object}

\begin{verbatim}
{
  "id": "W1",
  "type": "warehouse",
  "infinite_supply": false,
  "initial_inventory": {"SKU_A": 200, ...},
  "holding_cost": {"SKU_A": 0.05, ...},
  "shortage_cost": {"SKU_A": 1.0, ...},
  "order_cost_fixed": 10.0,
  "order_cost_per_unit": {"SKU_A": 0.01, ...},
  "policy": {
    "SKU_A": {
      "type": "base_stock",
      "base_stock_level": 500
    },
    ...
  }
}
\end{verbatim}

\textbf{Supported policy types:}
base\_stock, ss, rq, order\_up\_to,
periodic\_review, km\_cycle, echelon\_stock.

%% -----------------------------------------------------------------------
\section*{Edge Object}

\begin{verbatim}
{
  "from": "W1",
  "to": "R1",
  "max_dispatch_wait": 3,
  "transport_options": [
    {
      "mode": "truck",
      "capacity": 10.0,
      "weight_capacity": 8000.0,
      "cost_full": 1500.0,
      "cost_half": 900.0,
      "cost_quarter": 600.0,
      "lead_time": 1,
      "min_dispatch_utilization": 0.0
    }
  ]
}
\end{verbatim}

\begin{description}
  \item[capacity] Volume capacity in m$^3$ per vehicle.
  \item[weight\_capacity] Weight capacity in kg (\texttt{null} = unconstrained).
  \item[cost\_full / cost\_half / cost\_quarter] Three billing tiers.
        \texttt{cost\_full} applies when utilisation $\geq 85\%$ (dedicated
        FTL or near-full load); \texttt{cost\_half} applies in the range
        $[50\%, 85\%)$ (consolidated LTL freight); \texttt{cost\_quarter}
        applies below 50\% (parcel/courier minimum).
  \item[lead\_time] Transit days (deterministic).
  \item[min\_dispatch\_utilization] Minimum load fraction before
        dispatch; \texttt{0.0} dispatches on any load.
  \item[max\_dispatch\_wait] Maximum days to wait before forced dispatch.
\end{description}

%% -----------------------------------------------------------------------
\vspace{2em}
\section*{Disruption Object}

\begin{verbatim}
{
  "node_id": "Supplier",
  "start_day": 100,
  "duration": 14
}
\end{verbatim}

During days 100--113 (inclusive), the specified node will not
receive or dispatch any stock.  Orders placed by its children accumulate
as backlog and are served when the node recovers.
